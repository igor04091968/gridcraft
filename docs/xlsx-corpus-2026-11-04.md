```sh

git -C "$GRIDCRAFT_CORPUS_DIR" checkout --detach FETCH_HEAD
(cd "$GRIDCRAFT_CORPUS_DIR" && sha256sum --strict --check "$GRIDCRAFT_PROJECT_DIR/docs/corpus/calamine-ad7f2fa.sha256")

target/debug/gridcraft-cli check "$GRIDCRAFT_CORPUS_DIR/tests" --json --max-report 10 > /tmp/gridcraft-corpus.json
```

Последняя команда возвращает 1 при любом расхождении: это диагностический результат, а не ошибка запуска. Перед прогоном существующего checkout обязательно повторить проверку SHA-256. Для побайтового повторения используются ровно файлы манифеста; в чистом pinned checkout это все `tests/*.xlsx`.

## Что исправлено

1. **Потеря стандартных core properties.** Reader сохранял только title, subject, creator, keywords и description; created, modified, lastModifiedBy, revision и другие стандартные поля исчезали. В книгах без автора/названия это приводило к пустому core.xml. Теперь `DocProps`, XLSX reader и writer сохраняют все стандартные core properties, включая исходные даты и часовые смещения. Новый timestamp при сохранении не придумывается. Старый JSON модели продолжает открываться благодаря значениям по умолчанию.
2. **Strict extended properties.** Strict использует суффикс `extendedProperties`, transitional — `extended-properties`. Reader не распознавал первый вариант, а CLI считал его исчезновением связи при корректной смене формата. Теперь нормализуются обе записи; Company из Strict-книги тоже читается.
3. **Проверка метаданных.** В `check` добавлена категория `docProps`: изменение стандартных свойств между моделью и повторным чтением теперь обнаруживается. Это добавочное поле схемы `gridcraft-check/1`.
4. При полном CI обнаружены lint-ошибки прежнего AI-кода. Три выражения упрощены без изменения поведения; список провайдеров использует обязательный для проекта `craft_ui::ComboBox`. В четырёх native-only функциях bridge отмечено разрешённое `clippy.toml` использование desktop-часов, по образцу `control_server.rs`; запрет для WASM не изменялся.

5. **Доступные имена AI-панели.** Offscreen-проверка обнаружила четыре неназванных элемента (провайдер, модель, диапазон и задача). Поля связаны с существующими подписями; добавлена проверка с включённым accessibility checker.

6. **Новые файлы были доступны группе при umask 002.** Полный CI выявил, что новый workbook создавался с режимом 664. Unix writer теперь задаёт 0600 при создании новой книги и сохраняет ограничения существующей; регрессионная проверка требует отсутствия доступа для группы и остальных пользователей.

Регрессии создают пакеты в Rust, проверяют transitional/Strict import, текст с XML-экранированием, timestamp с часовым смещением, сохранение и чтение обратно, совместимость старого JSON и обнаружение потери метаданных. Внешние бинарные fixtures в тесты не встроены.

## Осталось проверить

- `errors.xlsx`, `Feuil1!A7`: сохранённый результат `VLOOKUP(B1,B1,B1,3)` — `#N/A`, GridCraft — `#VALUE!`. Единственное расчётное расхождение этого набора. B1 в исходном листе отсутствует. Нужна сверка свежего результата в Excel: изменение приоритета ошибок по одному неизвестно насколько свежему кешу не внесено.
- Расхождения `rdRichValueTypes` в двух книгах устранены и проверены повторным прогоном ниже; открытие в Excel остаётся непроверенным.
- `invalid_relationship_errors.xlsx` отказан из-за неверной ZIP checksum; `password_protected.xlsx` требует пароль. Это отдельные диагностические случаи, не исправленные «путём принятия» повреждённых или зашифрованных данных.
- `pivots.xlsx` имеет предупреждения о неподдержанном группировании полей; отдельные фонетические fixtures сообщают о некорректных/конфликтующих чтениях. Чистый round-trip модели не означает, что reader сохранил всё содержимое исходного ZIP.
- Не проверены 100 MB книги, сложные диаграммы, полнота slicers/timelines/Power Pivot, длительные прогоны и ремонт в Excel. Этот набор не закрывает XLSX beta gate и не обосновывает общий процент совместимости.
